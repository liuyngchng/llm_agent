### 0.4 公共组件包 (Common Lib)

## Phase 1：核心业务（可并行开发）

### 1.1 知识库服务 (Knowledge Base)
> 燃气行业专属知识的结构化存储、检索与管理。

- [ ] 文章/文档 CRUD，支持分类标签（报装、安检、缴费、漏气、改管…）
- [ ] 知识版本管理（草稿 → 审核 → 发布 → 下线）
- [ ] 富文本编辑 + 图片/附件上传
- [ ] 知识向量化入库（Embedding → Milvus / Qdrant）
- [ ] 检索增强：关键词搜索 + 语义搜索 + 混合召回
- [ ] 知识效果统计（引用次数、解决率、反馈）
- **技术栈：** Python(FastAPI) 或 Java，Milvus/Qdrant，Elasticsearch
- **难度：** ⭐⭐⭐⭐ | **预估工时：** 8~12 天

### 1.2 FAQ 服务
> 高频问题的快捷匹配与自助查询。

- [ ] FAQ 条目管理（问题/答案/分类/优先级/生效时间）
- [ ] 精准匹配（关键词 + 正则 + 同义词）
- [ ] 相似问题推荐（"你可能还想问…"）
- [ ] 热门 FAQ 排行、搜索无结果统计 → 自动生成 FAQ 建议
- [ ] 话术模板（引导语、结束语、忙碌时回复等）
- **技术栈：** Java / Python，Redis 缓存热点 FAQ
- **难度：** ⭐⭐⭐ | **预估工时：** 5~7 天

### 1.3 智能问答服务 (Q&A Service)
> 基于 LLM 的深度问答，整合知识库 + FAQ + 对话上下文。

- [ ] Prompt 模板管理与多轮对话上下文拼接
- [ ] RAG 链路：意图理解 → 知识检索 → 答案生成 → 引用溯源
- [ ] 安全围栏：敏感词过滤、越狱检测、回答兜底
- [ ] 回答质量评估（有用/无用 → RLHF 反馈回路）
- [ ] 流式输出（SSE / WebSocket），支持打字机效果
- [ ] 多模态支持（用户发图片：燃气表读数 OCR → 自动录数）
- **技术栈：** Python (LangChain / LlamaIndex)，LLM API 封装
- **难度：** ⭐⭐⭐⭐⭐ | **预估工时：** 12~18 天

### 1.4 意图识别服务 (Intent Recognition)
> 理解用户真正想做什么，是对话路由的中枢。

- [ ] 意图分类：咨询、报修、投诉、缴费查询、账单、开户、过户……
- [ ] 槽位提取（地址、户号、时间、金额、故障类型）
- [ ] 意图置信度分级：高置信 → 直接路由，低置信 → 追问澄清
- [ ] 人机协作：模型标注 + 人工复核 → 持续迭代
- [ ] AB 实验框架（对比不同 prompt/模型效果）
- **技术栈：** Python，LLM Function Calling / Structured Output
- **难度：** ⭐⭐⭐⭐ | **预估工时：** 7~10 天

### 1.5 对话管理服务 (Dialog Manager)
> 对话状态机：一次完整服务流程的生命周期管理。

- [ ] 会话生命周期：创建 → 进行中 → 待转人工 → 已转接 → 已结束
- [ ] 对话上下文窗口管理 & 自动摘要（超长对话压缩）
- [ ] 多轮对话策略：追问、确认、澄清、转人工
- [ ] 情绪识别：从文本判断客户情绪（正常/急躁/愤怒）
- [ ] 会话存档与追溯
- **技术栈：** Java / Go，Redis 存储会话状态
- **难度：** ⭐⭐⭐⭐ | **预估工时：** 8~12 天

### 1.6 智能体编排服务 (Agent Orchestration)
> 多 Agent 协作完成复杂业务——系统的大脑。

- [ ] Agent 注册与生命周期管理
- [ ] 编排引擎：Chain（链式）、Router（路由）、Parallel（并行）
- [ ] 内置 Agent：
  - "安检预约 Agent"：查时段 → 锁定名额 → 确认 → 生成预约单
  - "漏气应急 Agent"：判断严重性 → 推送安全指引 → 自动生成紧急工单 → 通知维修队
  - "缴费引导 Agent"：查账单 → 生成支付链接 → 确认到账
- [ ] Agent 间的上下文传递与结果聚合
- [ ] 人工审批节点（高危操作需人工确认）
- [ ] Agent 执行可视化（DAG 图，方便运营查看）
- **技术栈：** Python (LangGraph / CrewAI)，或 Java 状态机
- **难度：** ⭐⭐⭐⭐⭐ | **预估工时：** 15~22 天

## Phase 2：人工服务与工单

### 2.1 人工转接服务 (Human Handoff)
> AI ↔ 人工的平滑切换，不让客户感到断裂。

- [ ] 转接触发条件配置：意图置信度低 / 情绪愤怒 / 用户主动要求 / Agent 执行失败
- [ ] 转接时携带完整对话摘要 + 客户画像 + 当前上下文
- [ ] 客服分组与技能路由（抄表组、维修组、投诉组…）
- [ ] 排队策略（先到先得 / 紧急优先 / VIP 优先）
- [ ] 等待安抚（排队位置通知、预计等待时间、AI 预处继续聊天）
- [ ] 客服状态管理：在线/忙碌/小休/离线
- **技术栈：** Java / Go，WebSocket + 消息队列
- **难度：** ⭐⭐⭐⭐ | **预估工时：** 8~12 天

### 2.2 实时消息服务 (Message Service)
> 低延迟、高可靠的用户 ↔ 客服消息通道。

- [ ] WebSocket 长连接管理
- [ ] 消息类型：文本、图片、文件、语音、卡片（账单卡片、预约确认卡）
- [ ] 消息可靠投递（ACK 机制，断线重连后补推）
- [ ] 消息漫游（历史消息拉取）
- [ ] 敏感信息脱敏（手机号、身份证、银行卡在传输层处理）
- **技术栈：** Go / Java Netty，MQ（Kafka/RabbitMQ），Redis Pub/Sub
- **难度：** ⭐⭐⭐⭐ | **预估工时：** 7~10 天

### 2.3 工单服务 (Ticket Service)
> 需要线下处理的业务（上门维修、开户勘测）创建工单闭环。

- [ ] 工单生命周期：创建 → 派单 → 接单 → 处理中 → 完成 → 回访
- [ ] 自动派单规则（区域、技能、负载均衡）
- [ ] SLA 监控与超时告警
- [ ] 工单模板（报修、安检、改管、通气、拆改…）
- [ ] 维修人员 APP 端接口（接单、导航、现场拍照、完单签字）
- **技术栈：** Java，工作流引擎（Flowable / Camunda）
- **难度：** ⭐⭐⭐⭐⭐ | **预估工时：** 12~18 天

- [ ] 对话界面（类似微信聊天）

- [ ] 服务评价（解决/未解决 + 打分 + 文字反馈）

### 3.2 客服工作台 (Agent Workbench)

- [ ] 会话列表（排队中 / 我的会话 / 已结束）
- [ ] 对话面板（实时消息 + AI 推荐回复 + 快捷话术库）
- [ ] 客户信息侧边栏（基本信息、历史交互、历史工单、画像标签）
- [ ] AI 辅助：实时转写语音、自动摘要、情绪提醒、推荐答案

- **难度：** ⭐⭐⭐⭐ | **预估工时：** 12~18 天

## 通信协议约定

所有微服务之间统一使用以下方式通信：

- **同步调用：** HTTP RESTful API（OpenAPI 3.0 文档先行）
- **异步消息：** Kafka / RocketMQ（统一 Topic 命名规范 `gas.cs.{domain}.{event}`）
- **实时推送：** WebSocket（仅消息服务对外暴露，内部走 MQ）
- **服务发现：** Nacos
- **链路追踪：** SkyWalking / Jaeger（每个服务注入 traceId）

## 开发约定

1. 每个微服务独立 Git 仓库（或 Monorepo 独立模块），独立部署
2. API 文档先行——先写 OpenAPI spec，再写代码
3. 服务间不共享数据库，通过 API 通信
4. 所有接口带 TraceId，方便排错
5. Docker Compose 一键本地启动全链路
